# 0003. Error model

Planning decision: AD-06 (error model, end to end).

## Context

Every endpoint must answer errors with a problem document, clients need to branch on status and on a stable type for the two cases that carry extra data, and no response may leak internal detail. The PHP template mixes error shapes and has no single table.

## Decision

Four levels, each with one conversion. Domain errors are `thiserror` enums per concept with no HTTP knowledge. Application errors are one enum per bounded context. Bus errors wrap the application error or report a missing handler. The problem, `shared_application::http::Problem`, implements the response with `content-type: application/problem+json`; each application error converts into it in its own crate, and the shared crate converts bus errors, axum rejections and validation errors.

Every 5xx problem is created in one function that logs the error chain once at ERROR and returns a body without internal detail. A single table fixes status, `type`, `title` and `detail` for each situation. The statuses are 400, 404, 405, 413, 415, 422, 500 and 503. The `type` is `about:blank` when the status says everything, and a relative reference for the validation problem (`violations[]`) and the dependency problem (`failures[]`). There is no 409: ids are generated by the service, so a duplicate cannot be reached through the API.

## Consequences

One table binds every handler, the API contract and the Gherkin features. Relative problem types avoid a host name in the contract and stay valid in downstream services. GraphQL operation errors are not problem documents; they use `errors[]` with a stable `extensions.code`. `Problem` stays under 128 bytes so that `clippy::result_large_err` does not fire. A failed event publication after a successful save is not an error of the request.

Alternatives rejected: the `problem_details` crate (its schema support targets another utoipa major version), `about:blank` everywhere (clients could not tell a validation problem from another 422), and absolute type URLs under the repository (they hard-code the template name).
